最初に、小さな機能をプロジェクトに追加しました。より大きな変更には、さらにしっかりしたプロセスが必要です。GitHub Copilot CLI は既存の組織の開発フローに合わせて作業できるため、適切なものを適切な方法で構築できます。このレッスンから、エージェントを使った一般的な開発プロセスに沿って作業します。Issue を使って機能を計画し、コードが妥当であることと機能が意図どおりに動作することを確認してから、プロジェクトにマージします。

> [!NOTE]
> 機能のワークフローを続ける間は、同じ会話とブランチを使います。通常はファイルの種類ごとにブランチや PR を分けますが、ここでは中心的な概念に集中できるよう手順を簡略化しています。

このレッスンでは、次のことを行います。

- GitHub Issue から新しい Copilot の会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- 転送したブラウザーで機能を手動で検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズして、MCP による検証を追加し、QA エージェントを作成して、機能の PR を作成します。

## シナリオ

Tailspin Toys のカタログが拡大し、訪問者はカテゴリや発行元でゲームを絞り込む必要があります。バックログの Issue には機能の説明がありますが、カテゴリを組み合わせる方法など、コーディングの前に合意が必要な詳細があります。Plan モードで決定事項を整理し、その後、範囲を定めた実装を Autopilot に許可します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本原則は変わりません。むしろ、これまで以上に重要になります。多くの開発者は、次のような流れで作業します。

1. 実装内容を記載した Issue から始めます。
2. 構築する内容を計画します。
3. コードを構築してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューが完了し、継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 詳細な進め方はチームや組織によって異なりますが、多くの場合、上記の流れに沿っています。

この標準的な方法に従うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じ確認プロセスを経るようにします。

## 会話モード

**会話モード**は、エージェントがどの程度自律的に作業するかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: 開発者とエージェントが協力して作業します。エージェントは変更を提案し、続行する前に入力を待ちます。
- **Plan**: エージェントは最初に計画を作成し、プロジェクトファイルを編集できません。
- **Autopilot**: エージェントが自律的にコードを書き、テストを実行し、タスクが完了したと判断するまで反復します。

最初に Plan モードを使って計画をレビューし、次に Autopilot で実装します。

## Issue から始める

フィルター機能に着手する前に、Codespace に戻ってリポジトリとターミナルを準備します。

1. Codespace に戻ります。停止している場合は、再起動してから続行します。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新してから、フィルター機能用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を2回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押して、すべての Issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの Issue を選択します。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が追加されていることを確認します。`#` を使うと、GitHub 上の Issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てると、Copilot に作業を任せる前に、機能の実装方法やタスクの進め方を決められます。複雑な作業は、少し時間をかけて計画するのがお勧めです。Plan モードに切り替えて、計画の作成を依頼します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した Issue への参照に続けて、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調査してから、最適な方法を判断し、計画を作成します。

3. フィルター機能の動作について Copilot から質問されたら、希望に沿って答えます。正解が1つに決まっているわけではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画をスクロールして確認します。
6. 決定内容と異なる箇所があれば、修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot では、Copilot がタスクを完了したと判断するまで問題に取り組み、反復して改善します。

1. **Accept plan and build on autopilot (recommended)** またはインストール済みのバージョンで同様のラベルが付いた選択肢を選びます。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると実装がすぐに始まる場合があるため、先に計画をレビューしてください。Copilot から依存関係の不足やポートの競合が報告された場合は、チェックが完了したと判断する前にセットアップの問題を解決します。

## 実装をレビューして検証する

コードをマージする前に、ほかのコードと同じようにレビューします。コードを確認し、サイトを実行して動作も確かめます。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** または **Autopilot** がないことを確認します。
2. `/diff` を入力し、フィルター機能の実装とテストを確認します。
3. 結果を Issue と計画時の決定内容と照らし合わせます。
4. コードのレビューが完了したら、<kbd>Esc</kbd> を押して差分表示を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば修正を依頼します。

## 新しい機能を試す

コードに問題がなさそうでも、実際に動作するかを確認します。前回と同じようにアプリを起動し、Codespaces が転送したポートからサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces にポート `4321` が利用可能と表示されたら、**Open in Browser** を選択します。
3. カテゴリのフィルター、発行元のフィルター、計画で合意した組み合わせを試します。
4. リセットと該当結果がない場合の動作が、Issue と決定内容に合っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

異なる会話モードを使って機能を構築し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub Issue から Copilot の新しい会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで機能を実装しました。
- コードをレビューしました。
- 転送したブラウザーで機能を手動で検証しました。

次は、[カスタム指示を使って][next-lesson]、生成したコードが文書化された開発標準に従う方法を確認します。
