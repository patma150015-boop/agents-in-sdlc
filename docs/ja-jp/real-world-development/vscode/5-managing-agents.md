GitHub Copilot をエージェントモードで使うと、コードベースを調査し、変更を提案し、ファイルを編集して、コマンドを実行します。この作業は開発者のマシン上でリアルタイムに行われます。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集を確認できます。各差分をインラインでレビューして、変更を個別に承認または取り消し、追加のプロンプトを使って作業を調整、拡張できます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして適用します。
- 実行中のセッションでエージェントを調整し、高コントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、高コントラストモードを実装しています。作業中にデザインチームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を最初から始める代わりに、既存のセッションを調整して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 から Copilot Chat ビューに戻ります。
2. エージェントが作業する間、チャットをスクロールしてツール操作を確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択して変更を適用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツール操作で許可を求められる場合、エージェントは一時停止し、**Allow** プロンプトを表示します。許可するコマンドは、内容を確認してから選択してください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## ライトモードを追加するようエージェントに依頼する

高コントラストモードができたら、同じ会話を続けてライトモードの切り替えを追加します。以前の作業で変更したコンポーネント、スタイルの方法、設定をローカルストレージに保存する方法などのコンテキストは、同じチャットセッション内で保持されます。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業から続けて、既存の変更を確認し、ライトモードの追加を提案します。
3. 高コントラストの場合と同様に、新しい編集が届くたびにレビューします。各差分で **Keep** または **Undo** を使います。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好みに合わない方法で切り替え UI をリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止してから、明確にするための追加メッセージを送信します。

> [!TIP]
> 実行中のセッションを調整すると、最初からやり直すよりも早く進められます。追加プロンプトで「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」などの調整、「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する」などの軌道修正、「両方の切り替えにキーボードショートカットも追加する」などの範囲拡張を依頼できます。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開いて差分を確認します。カスタムエージェントのアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保持) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、実行中のセッションを監視して調整しました。ファイルの編集をその都度レビューして承認または取り消し、コンテキストを保持したまま追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を適用または取り消しました。
- 追加プロンプトを送信して、実行中のセッションを調整しました。

次のレッスンでは、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
